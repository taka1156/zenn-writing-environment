## この記事で伝えたいこと

- 今回作成したClaudeに作ってもらった解説や図解を、GitHub Pagesに貯めていくためのキット「MemoKit」を紹介します
- 実際に使ってみてハマったところ（デザインの統一、レビューやファクトチェック）も正直に書きます
- 読み終えると、Claudeを使って技術メモやナレッジを貯めていくやり方の一例がわかります

## 対象読者

- GitHubとClaudeをある程度使える人
- 基礎知識のキャッチアップに苦労している人
- AIに質問しても、その場で終わってしまい次に活かせていない人（あるいは聞いたこと自体を忘れてしまう人）

## 背景・課題

Claudeに気になる技術を聞いたり、わかりやすい図解を作ってもらったりすることはよくあります。
ところが、会話が流れていったり、聞いたこと自体を忘れてしまったりして、後から見返せません。

「この前Claudeに教えてもらった気がするけど、どの会話だったっけ…」という経験がある人も多いのではないでしょうか。

## 原因

原因はシンプルで、次の2つだと考えています。

- 会話は基本的に流れて消えていくものであること
- 内容を貯めておける場所が、自分の記憶しかないこと

つまり、会話の外に「貯める場所」と「貯める仕組み」があれば解決できるはずです。

## 解決策：MemoKitを作った

そこで、**MemoKit** というテンプレートリポジトリを作りました。

https://github.com/taka1156/memo-kit

Claudeに「〜の図解ページを作って」「さっきの説明をメモにして」のように頼むと、Claudeが依頼に合ったスキルを選び、決まったフォーマットでページにまとめてpushしてくれます。pushされたメモはGitHub Actionsでビルドされ、GitHub Pagesで公開されます。

:::message
ClaudeからGitHubに書き込むため、ClaudeとGitHub Appの連携が必要です。
:::

### 特徴

主な機能は次のとおりです。

- **llms.txtなどによる簡易的なAI対応**
  ビルド時に各メモをMarkdownにした版と `llms.txt` を生成します。公開URLを渡せば、リポジトリを繋いでいない会話でもClaudeが過去のメモを読めます。
- **サブエージェントによるファクトチェックとデザインの確認**
  メモの本文を変えてpushする前に、サブエージェントが独立して事実確認をします。新しいページや図を変えたページは、スマホ・PC × ライト・ダークモードで表示崩れや色を確認します。
- **lint・buildによるフォーマットの統一とOGP対応**
  一覧やメタタグ、OGPなどの共通部分はビルドで自動生成するので、メモ本体を書くことに集中できます。
- **確認クイズ（オプション）**
  メモを流し読みで終わらせないための機能です。
- **ロードマップ（オプション）**
  ある分野を体系的にまとめたいときに、方向性がぶれないようにするための機能です。

依頼の内容に応じて、Claudeは次のようなスキルを使い分けます。

| 頼み方の例 | スキル | やること |
| --- | --- | --- |
| 「〜の図解ページを作って」 | `memo-style` | デザイン規約とテンプレートに沿ってページを作り、プレビューを見せる |
| 「さっきの説明をメモにして」 | `memo-from-chat` | 会話の内容をページにして、ファクトチェックを経て登録 |
| 「このHTMLをメモに入れて」 | `memo-publish` | 崩れの修正、タイトル・タグ付け、一覧の更新、ファクトチェック、push |
| 「〇〇をファクトチェックして」 | `memo-factcheck` | サブエージェントで事実確認して指摘を報告 |
| 「前に〜のメモ書いたよね」 | `memo-reference` | 過去のメモを探して読む・部分的に直す |
| 「ロードマップを作って」 | `memo-roadmap` | ロードマップの項目決めや、次に書くメモの作成 |

:::message
「作って」「まとめて」「図解して」だけの場合は、会話内でプレビューを見せるところまでで止まります。保存（push）するのは「保存して」「メモにして」など保存を頼む言葉があるときだけです。
:::

## 環境・前提条件

- GitHubアカウント（GitHub PagesとGitHub Actionsを使います）
- Claude（GitHub Appを連携して、リポジトリへの読み書き権限を渡せること）
- 手元でビルドや表示確認をしたい場合のみ：Python 3.8以上、Git

:::message alert
GitHub Pagesで公開したメモは、インターネット上の誰でも読めます。GitHubの無料プランではPagesは公開リポジトリでしか使えないため、リポジトリ自体も公開になります。社外秘の情報や個人情報、認証情報を含む会話はメモにしないようにしてください。
:::

## 導入手順

### 1. テンプレートからリポジトリを作る

以下のリポジトリを開き、「Use this template」→「Create a new repository」で自分用のリポジトリを作ります。

https://github.com/taka1156/memo-kit

テンプレートにはサンプルのメモが2本入っているので、不要なら消しておきます（Claudeに頼んでも構いません）。

### 2. ClaudeとGitHub Appを連携する

ClaudeとGitHub Appを連携し、作ったリポジトリへの読み取り・書き込み権限を渡します。

### 3. Claudeにリポジトリを伝える

新しい会話を始めたら、最初に「`<owner>/<name>` リポジトリで作業して」と伝えます。Claudeがリポジトリを取得し、中のスキルに沿って動くようになります。

### 4. `memo.config.json` を設定する

サイト名やリポジトリ名などを `memo.config.json` に書きます。自分で書いてもよいですし、「対話形式で設定項目を聞いて、`memo.config.json` を書いて」とClaudeに頼んでも構いません。

```json:memo.config.json
{
  "site_name": "MyNotes",
  "description": "Claude に作ってもらった解説ページの置き場",
  "llms_description": "Claude に作ってもらった解説ページの集まり。",
  "repository": "alice/my-notes",
  "branch": "main",
  "deploy_branch": "dist",
  "utc_offset_hours": 9,
  "quiz": true,
  "roadmap": false,
  "branding": { "accent": "#00d4ff", "accent_light": "#0077b6", "theme": "dark" }
}
```

クイズとロードマップは、ある程度体系的にまとめたい人や、メモの素通りを防ぎたい人向けの機能です。不要であれば `false` にしてください。

:::details 設定項目の一覧

| 項目 | 内容 | デフォルト値 | 影響するところ |
| --- | --- | --- | --- |
| `site_name` | サイト名 | `MEMO` | OGP、ページのtitleタグ、トップページの表記 |
| `description` | トップページの説明 | 空 | OGP |
| `llms_description` | `llms.txt` の冒頭の説明 | 空 | AI向けの `llms.txt` |
| `repository` | GitHubの `owner/name` | 空（`build` が警告） | GitHub Pagesで表示するときのページ間リンク |
| `branch` | 原本を置くブランチ | `main` | リポジトリのデフォルトブランチを指定します |
| `deploy_branch` | 公開用のブランチ（`branch` と同じにはできない） | `dist` | ビルド後のファイルの置き場所。metaタグなどの共通部分の付加、クイズやLLM向けMarkdownの生成をビルドで行うため、原本とは別のブランチにします |
| `utc_offset_hours` | 「今日」を決めるタイムゾーン | `0`（日本なら `9`） | メモの作成日 |
| `quiz` | 確認クイズを使うか | `true` | `false` にするとクイズを生成しません |
| `roadmap` | ロードマップを公開するか | `false` | まとめる分野をカテゴリごとに分け、埋まり具合を割合で表示します |
| `branding` | アクセント色と、アイコン・OGP画像の文字・色 | `{}` | OGP、テキストの強調、見出しなど |

:::

### 5. GitHub側の設定をする

最後に、GitHubのリポジトリ設定で公開の準備をします。

1. **Settings → Actions → General → Workflow permissions** を「Read and write permissions」にします（デプロイ用のワークフローが `dist` ブランチにpushするため）
2. 権限を付けたあとにpushする（またはActionsの画面から `Deploy MEMO` を実行する）と、`dist` ブランチが作られます
3. **Settings → Pages → Source** を「Deploy from a branch」にし、ブランチを `dist`、フォルダを `/ (root)` にします

### 6. あとは頼むだけ

「〜の図解ページを作って」「さっきの説明をメモにして」のように頼んで、日々のメモとして活用してください。

## 溜まったメモの活用方法

メモが溜まってきたら、こんな使い方をしてみてください。

- **カテゴリごとに見直す・書き足す**
  基本の使い方です。「この前Claudeに教えてもらった気がする」と思ったときに、スマホで気軽に見返したり、周りの人に共有したりできます。
- **確認クイズを解く**
  ランダムに10問、カテゴリを絞って10問、制限時間内に何問解けるかを競うタイムアタックから選べます。
- **内容が古くなっていないかClaudeにレビューしてもらう**
  Claudeで運用する前提の作りなので、「少し古いかも」と思ったら気軽に更新を頼めます。

## さらにカスタマイズしたい人へ

もう少し手を加えたい人は、次のようなことを試してみてください。

- スキルを改造して、自分の見やすいUIに変える
- サブエージェントのレビュー観点を追加して、チェックをより厳しくする

## 使ってみた結果

- メモをこまめに見返す習慣がついた
- メモの内容を起点に、さらに深掘りしたり調べたりする習慣がついた
- 業務で使っているけれど意外と理解してない知識を、気軽にまとめられる環境ができた

## 留意点・今後の課題

まだ成熟しきっていないので、粗いところがあります。特に次の2点は調整中です。

- **デザインの統一**
  図をClaudeに自由に作ってもらうため、あえて縛りを緩くしている部分があります。ただ、共通部分の見た目がページごとにばらつくとそちらに目がいってしまうので、どこまで揃えるかを調整しています。
- **レビュースキルの精度**
  レビューの観点、用語の表記ゆれ、一般的な用語かどうかの判断などに、まだ調整の余地があります。

## まとめ

- Claudeとの会話は放っておくと流れて消えてしまうので、会話の外に「貯める場所」と「貯める仕組み」を用意しました
- MemoKitを使うと、Claudeに頼むだけで図解つきのメモがGitHub Pagesに溜まっていきます
- ファクトチェックや表示確認をサブエージェントに任せることで、ある程度の品質を担保しながら気軽に貯められます

テンプレートから数ステップで始められるので、AIとの会話を「その場限り」で終わらせたくない人は、ぜひ試してみてください。
